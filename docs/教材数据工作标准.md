# 教材数据工作标准

本标准依据项目需求和已有工作的经验制定，用于验收一至六年级语文教材数据。先判断交付是否满足标准，再选择执行方法。发生冲突时，以用户最新明确指令为准。

交付标准规定必须实际交付和验证的结果；执行标准规定达到结果的方法与顺序。过程记录、尝试次数和局部结果不能代替验收证据。

## 目标与范围

以统编版人民教育出版社小学语文教材为基础，整理一年级至六年级、上册和下册的写字表、词语表、古诗词和日积月累；逐项核对字词及正文的拼音，供记忆和练字使用。教材是第一信源，《现代汉语词典》是第二信源；不以其他来源替代两者。

## 交付标准

### 第一阶段：官方教材 PDF

- 从国家中小学智慧教育平台直接下载人教版语文教材 PDF，一至六年级每年级上、下册各一份，共 12 份。第三方镜像和由网页图片重新拼成的 PDF 不能冒充平台下载的原始 PDF。
- 每份记录年级、册次、平台教材页面及实际下载来源、平台显示的版本信息、下载日期、文件大小、页数和 SHA-256；版本信息未明确时如实标注，不因文件更新时间推定版次。清单和提交内容不得包含登录凭据、令牌或带凭据的临时链接。
- 对每份文件检查 PDF 结构、是否能正常打开及首尾页、目录和页数，确认年级、册次和页面连续完整；平台提供可核验的原始文件大小、哈希或页数时逐项比较。平台未提供某项时记明其缺失，并用可获得的证据检查完整性，不能把本地计算的哈希当成平台提供的原件哈希。
- 12 份文件及对应清单提交至指定 GitHub 仓库，记录分支和提交号；从远程逐份取回文件并比较 SHA-256，验证远程保存的是完整文件，而非占位文件。不得仅提交链接、清单或本地路径。

**验收条件：**12 份官方原始 PDF 均已下载、检查并提交到远程，逐册信息和校验结果可查。任一文件缺失、来源或完整性未确认、远程提交未成功，第一阶段均未完成。

### 第二阶段：《现代汉语词典》查询方式

- 找到网上可用的《现代汉语词典》查询版本，优先 API；记录提供方、词典版本、入口、可用性和使用限制。
- 实际查询有代表性的单字、词语、多音字和轻声词，检查结果能否提供读音和必要义项，并测试能否批量查询及追溯结果；测试记录包括查询项、结果、日期和受限情况。
- 没有找到可用 API 时，如实说明已检索的范围，提供经实际测试可用于核对的在线查询方式及其限制；不能据此声称所有 API 都不存在。不可用的入口、仅有摘要而不足以核对的结果、未验证的接口或其他词典不能计为完成。

**验收条件：**提供经实测可用的查询方式和测试结果，清楚说明能否批量处理及其限制。

### 第三阶段：数据、核对与部署

- 两份 CSV 分别交付字词和诗词、日积月累，包含既定表头、稳定 ID、年级、上下册、名称、对应内容、拼音和供人查看的核对状态。字段结构遵循项目 README；状态不显示在页面。
- 与第一阶段教材逐册、逐课、逐栏目比较，检查覆盖、归属、顺序及正文；已确认遗漏的内容补入，无法确认的内容留空并标明，不用猜测填充。
- 对每个汉字、词语和正文中每个字音独立核对：将已有注音作为候选，与适用的教材注音或词典条目比较，而不是用生成候选的结果自证。教材直接标音时以教材为准；教材未标音时，依据《现代汉语词典》并结合具体词义和语境核对。不同课文、不同词义的同字或同词须分别确认，不能仅凭同形自动判定。
- 词典查询以商务印书馆官方接口为主，Toocix 仅作为辅助线索，不能单独用于标记已核对。官方接口未返回整词时，可查询相关词条或单字并结合教材语境判断；依然无法确认的按缺失处理，不凭猜测填充。官方数据库标示第五版，发生版本或来源分歧时记录依据并以最新版人教教材优先。
- 遇到分歧时记录具体字词、教材或词典的不同读法及采用依据；教材和词典不能确定的部分留空并标注。来源不可访问、未查询或未核实的项目不得标为已核对。对教材或词典已能确定、但另一来源存在不同读法的项目，采用指定优先级并记录分歧，不把已解决的分歧反复当作阻塞。
- 两份 CSV 原有字段保持不变，核对状态供逐行查看；若一行包含多个字词，另以可追溯记录定位到 CSV 文件、ID、字段和位置，并记录教材册次与页码或词典词条、核对结果及分歧。整行只有在其中每项都完成核对或已按要求标明分歧、缺失后才能标为整行处理完毕。
- 逐项状态区分「已核对」「已核对，有分歧」「缺失或无法确定」「未核对」；前两类必须有对应依据。缺失或无法确定表示已检查后仍不能确认，未核对表示尚未完成检查。报告分别给出各类数量、总数及统计单位，不能把未核对计入已处理或把按行比例说成按字比例。
- 现有 CSV 每行可能包含多个拼音，而构建脚本要求非空拼音与汉字数对应。对某个音节需留空的情况，须先验证并实现能够准确保留位置、构建通过且页面正确显示的表示方法；不得随意使用已用于儿化的 `_` 或让后续拼音错位。此项只在第三阶段处理。
- 提交两份 CSV 及必要核对记录，按项目构建方式生成网站并推送部署；检查构建结果、GitHub Pages 部署状态，以及线上代表性字词和诗词页面的内容、拼音和访问。

**验收条件：**12 册教材的范围均已逐项检查，逐项状态中「未核对」为零；每个读音的实际状态与证据可追溯；已检查但确有分歧或缺失的项目按上述规则标注或留空。CSV 与线上页面一致，远程提交和部署均经验证。项目总数以教材实际范围为准，不以既有 CSV 行数代替教材覆盖率。

## 执行标准

1. **顺序不可跳过。**先完成并验收第一阶段，再开展第二阶段；第二阶段验收后才进行第三阶段。第一阶段有未完成项时，不转做词典查询或词条核对。用户明确另行安排的工作除外。
2. **先验证依赖，再批量执行。**第一阶段先确认平台下载入口和访问权限，再下载全套并逐册验收；第二阶段先用代表性查询验证可用性和限制，再确定批量核对方式。下载、校验或推送失败时先核实终止状态与失败原因，再针对失败部分重试，不重复已完成工作。
3. **按册、按批次处理。**以一册教材或可核验的一批词条为工作单位，批量提取、比对和记录；对多音字、轻声、儿化、变调、古文语境及来源冲突逐项判断。机械统计和结构校验可用程序完成，但程序生成候选或形式匹配不等于独立核对。
4. **只用指定信源作结论。**教材优先，词典补充；不把第三方转录、类似例句、猜测、程序输出或其他资料当作核对结论。教材版本、词义或读音不能确认时如实记录，继续处理不依赖该疑点的其他项目。
5. **明确状态和证据。**区分实际下载与查看、直接注音与语境判断、已查询与已核实。状态只反映已完成的核对；一处疑点不得掩盖同一行其他项目的完成情况。
6. **在验收点提交。**每阶段形成完整、可检查的结果后提交；提交前检查工作区，保护其他未提交修改；提交后检查远程结果。对网络中断或权限不足，记录具体失败环节、已完成部分和继续所需条件，不声称成功；不得转入下一阶段。
7. **按交付衡量进度。**分别报告三个阶段是否达到验收条件，以及第三阶段各类项目数量；不得将注释增加、候选生成或局部参考视为整项完成。
